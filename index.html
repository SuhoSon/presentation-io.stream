데이터 배치 제어권을 시스템 운영자(cgroup)에게!
논문의 핵심 요지 ("Who Decides Stream?")

최신 SSD 기술인 FDP(Flexible Data Placement)를 애플리케이션 소스코드 수정 없이, cgroup(컨테이너) 단위로 데이터 배치를 제어할 수 있는 시스템 아키텍처를 제안합니다.

쓰기 증폭(WAF)의 발생 원인과 한계

  • 비대칭적 구조: SSD는 쓰기 단위(Page)와 지우기 단위(Block)의 크기 불일치 현상이 존재합니다.
  • GC 오버헤드: 상이한 업데이트 주기를 가진 데이터가 동일 블록에 혼재될 경우, 잉여 공간 확보를 위해 유효 데이터(Valid Page)를 다른 블록으로 복사(GC)해야 합니다.
  • DWPD와 OP의 트레이드오프: WAF의 증가는 NAND 소모를 가속화합니다. 스펙 상의 DWPD(Drive Writes Per Day)를 보장하기 위해서는 디바이스 내 OP(Over-Provisioning) 비율을 늘려야 하므로 원가가 크게 상승하며, 반대로 OP를 유지할 경우 수명 보증 수치가 현저히 저하됩니다.
근본적 문제 제기: 호스트(OS)는 데이터의 특성(Hot/Cold)을 알고 있지만, SSD 컨트롤러는 이를 알지 못하는 '블랙박스(Black-box)' 구조로 인해 불필요한 데이터 혼재가 계속 발생합니다. 👉 이에 대한 해결책이 필요합니다.

기존 블랙박스 모델의 한계

  • 기존 SSD 컨트롤러는 호스트 워크로드의 의도나 수명을 인지하지 못한 채, 가용 블록에 데이터를 임의로 배치합니다.
  • 이에 따라 런타임 중 데이터 혼재 현상이 필연적으로 발생하며, WAF 및 Latency Spike를 유발합니다.

FDP의 핵심 원리

  • 호스트(OS/App)가 I/O 요청 시 데이터 수명 특성을 나타내는 Placement Identifier (PID)를 함께 전달합니다.
  • 디바이스는 수신된 PID를 기준으로 데이터를 별도의 물리적 블록 집합에 격리 저장하여, 블록 단위의 데이터 생명 주기를 동기화하고 GC를 최소화합니다.

1. Reclaim Group (RG)

플래시 미디어 내에서 독립적으로 GC가 수행되는 영역입니다. 다중 RG 간에는 미디어 레벨의 병렬성을 확보할 수 있습니다.

2. Reclaim Unit (RU)

FDP에서 관리하는 최소 스토리지 할당 단위로, 내부적으로 다수의 NAND Block들로 구성되어 실제 Erase 작업이 일어나는 단위입니다.

3. Reclaim Unit Handle (RUH)

SSD 컨트롤러가 현재 데이터를 기록하기 위해 열어둔(Open) 활성 RU를 지칭하는 내부 포인터 리소스입니다.

4. Write Stream

호스트가 데이터 생명 주기 격리를 위해 각 I/O 단위에 부여하는 식별자이며, 디바이스 내의 특정 RUH로 매핑됩니다.

기존 FDP 도입 방식의 구조적 한계 및 실증 사례

애플리케이션 및 파일시스템 계층 기반 제어의 문제점

1. Application-Driven 모델

  • 엔지니어링 비용: 상용 애플리케이션의 소스코드 직접 수정 필요.
  • 컨텍스트 유실: Buffered I/O를 거치며 커널 레벨에서 I/O 태그 정보가 유실됨.

2. FS-Driven 모델 (WARP 연구 실증)

  • 휴리스틱 예측의 불확실성: 파일 크기/확장자만으로는 실제 런타임 생명 주기를 정확히 추론할 수 없음.
  • 데이터 편향: F2FS에 제어를 일임하여 엔터프라이즈 워크로드를 구동한 결과, 전체 데이터의 99%가 단일 WARM 스트림으로 집중되는 현상이 관찰됨(FAST '26). 즉, 다중 RUH 분리 효과가 완전히 상실됨.

왜 Container (cgroup)가 이상적인 FDP 제어 단위인가?

효율적인 데이터 격리를 위한 최적의 Granularity

본 논문은 데이터센터 환경에서 컨테이너(cgroup) 단위가 데이터 수명 주기를 그룹화하고 FDP 스트림을 할당하기 위한 가장 이상적이고 실용적인 Granularity임을 제안합니다.

1. 모든 I/O Path에 내장된 컨텍스트

cgroup (blkcg) 식별자는 VFS부터 Page Cache, Block Layer에 이르기까지 모든 I/O 경로에 기본적으로 태깅되어 유지됩니다. 따라서 애플리케이션의 수정 없이도 정확한 I/O 출처 추적과 스트림 맵핑이 자연스럽게 이루어집니다.

2. 운영자(Operator) 친화적 관리 단위

데이터센터와 클라우드 환경의 시스템 운영자(Operator)는 이미 쿠버네티스(Kubernetes) 등 오케스트레이터를 통해 컨테이너(cgroup) 단위로 자원을 격리하고 관리하고 있습니다. 따라서 이를 FDP 스토리지 격리 기준으로 활용하는 것은 기존의 인프라 관리 체계와 완벽하게 부합합니다.

범용적 I/O 경로 지원 및 동작 시퀀스

  1. 다양한 I/O 경로 지원: 애플리케이션은 Buffered I/O(Page Cache 경유), Direct I/O(FS 직접 접근), 혹은 FS를 우회하는 Raw Device 접근 중 어떤 방식을 사용하더라도 io.stream의 데이터 격리 혜택을 받습니다.
  2. 컨텍스트 유지 (Buffered I/O): 비동기 Writeback 동작 시, 커널은 해당 Page를 더럽힌(Dirty) 원본 blkcg 컨텍스트를 정확히 역추적하여 Block Layer에 인가합니다.
  3. 컨텍스트 획득 (Direct I/O & Raw): I/O를 발행하는 현재 프로세스 컨텍스트에서 즉시 blkcg를 획득하여 Block Layer로 전달합니다.
  4. PID 변환 및 투명성: 상위의 어떤 경로를 거치든 모든 I/O는 Block Layer로 수렴합니다. 이곳에서 NVMe 커맨드 생성 시 cgroup ID를 디바이스 스트림 ID(RUH)로 매핑하므로 완벽한 호환성이 보장됩니다.

할당 정책(Policies) 및 시나리오 동작

  • 명시적 할당 (Explicit Policy): cgroup v2의 io.stream 속성 노드에 스트림 ID를 기록하면, 해당 테넌트에서 발생하는 모든 I/O는 지정된 RUH로 확정 매핑됩니다.
    echo "259:0 1" > /sys/fs/cgroup/Tenant_A/io.stream
  • I/O Hint 우선 (Bypass): 같은 cgroup에서 발생한 I/O라도, 이미 Stream ID가 명시적으로 지정된 I/O의 경우 cgroup 정책에 의해 덮어씌워지지 않고 기존 Stream ID를 유지합니다.
  • 기본 정책 (Default Fallback): 명시적으로 io.stream이 설정되지 않은 프로세스나 최상위 Root cgroup의 I/O는 모두 시스템 기본 스트림(RUH 0)으로 수렴합니다.
  • 🌟 메타데이터 자동 격리 (Free Metadata Isolation):
    ext4의 jbd2 저널링과 같은 커널/파일시스템의 내부 메타데이터 쓰기는 커널 스레드에서 생성되며 기본 Root 컨텍스트로 처리됩니다. 따라서 별도의 복잡한 FS 튜닝 없이도 사용자 데이터(RUH 1, 2)와 시스템 메타데이터(RUH 0)가 물리적으로 완벽히 격리되는 이점을 얻게 됩니다.

  • 스토리지 하드웨어: Samsung PM9D3a 4TB Datacenter FDP NVMe SSD

결과 분석 1: WAF 최소화 및 시스템 응답성(Latency) 대폭 개선

백그라운드 미디어 간섭 제거를 통한 SSD 컨트롤러 성능 최적화

데이터 생명 주기에 맞춘 물리적 격리로 인하여 디바이스 내부의 무효 페이지 회수(GC) 오버헤드가 사실상 소멸되었습니다. 이로 인해 NAND 대역폭 손실이 억제되었을 뿐만 아니라, 펌웨어 단의 락(Lock) 경합 및 인터럽트 병목 현상이 해소되어 호스트 단 p99 Latency가 최대 93%까지 대폭 개선되는 결과를 도출했습니다.

결과 분석 2: 스트림 프로비저닝 규모와 분배 정확도의 상관관계

다중 활성 스트림(RUH) 환경에서의 Coherence(결합도) 의존성 검증

스트림 분배 정책 별 WAF 관찰

  • Oblivious (무작위 균등 분배): 디바이스가 제공하는 최대 가용 스트림(7개)을 모두 프로비저닝하더라도, 워크로드 속성을 배제할 시 WAF는 2.36으로 현격히 악화됩니다.
  • Coherent (데이터 결합도 중심): 전체 워크로드를 정확히 핫/콜드 속성으로 양분하여 최소한의 스트림(2개)으로만 운용했을 때 최적 성능(WAF 1.0)이 관찰되었습니다.
  • 결과 고찰: 향후 FDP 인프라 설계 시, 물리적 스트림 자원의 양적 확보보다 호스트 스페이스 차원의 정합성(Coherence) 높은 매핑 정책 도입이 최우선시되어야 함을 시사합니다.

결과 분석 3: 장기 상용 데이터베이스 벤치마크 (12h)

다중 테넌트(Multi-tenant) 클라우드 환경 내 지속 성능 방어력 입증

상용 RDBMS / NoSQL 복합 운용 시나리오

  • 코드 레벨의 FDP 수용이 불가능한 상용 솔루션(RocksDB, Postgres, Kafka, Mongo) 4종을 대상으로, cgroup 단위 격리를 통해 12시간 동안 Continuous I/O 벤치마크를 수행했습니다.
  • 기존 혼재 방식(회색 점선)은 NAND 단편화 누적으로 인해 점진적으로 WAF 1.7에 수렴하였습니다.
  • 반면, io.stream 기반의 격리 적용 시(녹색 실선) 초기 상태의 WAF 1.2 마진을 워크로드 종료 시점까지 일정하게 유지하여 높은 시스템 안정성을 확인하였습니다.

향후 연구 및 발전 과제 (Future Directions)

자율형 동적 스트림 프로비저닝 및 펌웨어 리소스 최적화 방향

런타임 온라인 학습(Online Learning) 기반 정책 자동화

정적인 관리자 오버라이드 룰셋에서 탈피하여, 리눅스 I/O 스케줄러 계층이 런타임에 실시간으로 cgroup 단위의 쓰기 주파수 및 수명 주기를 샘플링하여 머신러닝 기법으로 스트림(RUH) 맵핑을 자율 조정하는 지능화 프레임워크 연구가 필요합니다.

제한적 Effective OP 환경을 고려한 스트림 병합 스케줄링

앞선 분석에서 규명했듯 다수의 물리 스트림 유지는 펌웨어 단의 공간 프로비저닝 비용(OP 확보 제약)을 동반합니다. 최소 필수 RUH 집합을 선별 유지하고, 생명 주기가 유사한 마이너 테넌트(Minor Tenants)를 휴리스틱 기반으로 클러스터링(병합)하는 스토리지 자원 극대화 알고리즘의 개발이 요구됩니다.

강력한 격리 수준(Isolation Level)은 디바이스 Effective OP 감소를 수반함

1. Conventional SSD

Effective OP: 최대 (Max) 데이터 격리: 수행 불가

전체 Free Block을 단일 글로벌 풀로 운용하여 디바이스 내 OP 비율이 극대화되나, I/O 워크로드 간 데이터 혼재가 발생합니다.

2. Initially Isolated (FDP)

Effective OP: 부분적 감소 데이터 격리: 초기 쓰기 시에만 유효

초기 호스트 기록(Host Write) 시에만 논리적 스트림을 유지하며, 공간 최적화를 위해 런타임 GC 도중 데이터를 병합합니다.

3. Persistently Isolated (FDP)

Effective OP: 매우 제한적 데이터 격리: GC 포함 완벽 격리

각 스트림(RUH) 단위로 독립된 GC 풀을 프로비저닝합니다. 완벽한 생명 주기 분리가 달성되나, 펌웨어 내 통합 가용 OP가 급감합니다.

결론 (Conclusion)

Host-Managed Storage 패러다임의 실효적 구현 및 향후 지향점

주요 연구 성과 및 의의

  • Zero-Modification 호환성: 레거시 워크로드 및 범용 파일시스템 스택의 코드 변형을 배제하여 NVMe FDP 기술의 실무 진입 장벽을 완전히 허물었습니다.
  • Operator-Driven 아키텍처: 시스템 운영자 관점의 cgroup 자원 경계를 물리 매체 영역(NAND Block)까지 1:1로 프로비저닝하는 아키텍처를 제시했습니다.
  • 이상적 성능 수렴: 커널 최적화를 통해 낭비 없는 대역폭 효율(WAF 1.0)과 데이터센터급 QoS 지연 요건을 충족시키는 성능 개선을 실증해냈습니다.
