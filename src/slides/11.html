평가 설정 — 그리고 왜 이렇게 측정했는가

후배들에게는 결과보다 이 슬라이드가 더 오래 쓸모 있습니다

플랫폼과 대조군

  • SSD: Samsung PM9D3a 4TB 데이터센터 FDP NVMe. OP 7%, 단일 reclaim group, RUH 8개 — 기본 1개(비귀속 메타데이터) + 데이터용 7개
  • 호스트: Intel Core i9-12900K / 64GB RAM / 수정된 Linux 7.0
  • 대조군은 동일 하드웨어·OP·펌웨어에서:
    · No-FDP — FDP 모드 자체를 끔
    · FDP-default — FDP는 켜고 스트림은 아무도 지정하지 않음. 오늘 무수정 스택이 FDP 드라이브에서 실제로 보는 상태
  • 3단계 실험: ① raw·ext4·xfs 세 경로 검증 → ② raw에서 매핑 정책 스윕 → ③ 무수정 컨테이너 4종 12시간
  • 모든 구성 3회 반복, 평균±표준편차 보고

리뷰어가 물고 늘어질 구멍을 미리 막는 법

  • 매 실행 전 nvme format 후 꽉 채웁니다.
    갓 포맷한 미디어에서는 WAF가 1 근처라 차이가 안 보입니다. 채워야 덮어쓰기가 즉시 GC를 돌립니다.
  • nodiscard로 실행합니다.
    TRIM이 끼면 회수가 배치 덕인지 호스트 힌트 덕인지 구분할 수 없습니다.
  • 파일시스템을 일부러 몰아붙입니다. (ext4 commit=1 등) jbd2를 계속 돌게 해서 메타데이터 경로를 실제로 자극하려는 것입니다.
  • WAF는 호스트가 아니라 디바이스가 잰 값입니다.
    SMART 로그 02h와 OCP 로그 C0h의 델타를 분당 샘플링해, 정상상태 구간의 비율로 계산합니다.
  • 실행 간 편차와 실행 내 편차를 둘 다 적습니다.
    "GC 피크를 찍은 게 아니라 안정된 고원"임을 증명하는 장치입니다.
💡 스토리지 실험에서는 측정 이전의 준비가 결과의 신뢰도를 결정한다.
자기 실험을 설계할 때 그대로 가져다 쓸 체크리스트. 특히 preconditioning과 nodiscard는 빠뜨리면 결과 전체가 무의미해진다.
